# 第一輪改善：行情日期、資料狀態與核心摘要

實作日期：2026-10-26。範圍跨網頁、資料處理與發布；整合 Claude `522ab50` 的休市防護，不改其既有分支。

## 資料修復

- 已核對的 10/23 臨時休市公告保存在 `data/market_closures.json`，用於交易日判斷、週申贖、主動式持股與發布查核。沒有公告時，不因資料缺漏推斷休市。
- 流動性充足的 Yahoo 探測標的，必須有正且有限的成交量，才可據此推進交易日。這不是把每檔零成交量 ETF 都判定成休市。
- 每日流程開始時，`history_corrections.apply` 只接受已核對 SHA-256 的 `daily/2026-10-23.csv`（先統一 LF 換行）。將原始資料隔離到 `history/quarantine/daily/`，附公告連結及原因，再移除錯誤日行情。內容不符則停止；重跑無副作用。
- 不移除 `holdings/`、`holding_lists/`、`fund_daily/` 的投信公告。隔離區不屬於 `store.TABLES`，不重建進 SQLite。
- 本 PR 不提交歷史 CSV 或 `latest.json`；隔離差異及重建結果由每日機器人提交。
- `release.validate_data` 從將提交的 CSV 重建記憶體資料庫，執行 audit 的所有阻擋檢查。提交前、推送前及產生發布成品時均執行；有錯或無法查核就停止。提醒項目仍需另行追查，通過不等於全部資料皆正確。

## 網頁資料合約

`latest.json.market_status` 第 1 版：

| 欄位 | 口徑 |
| --- | --- |
| `version` | 1 |
| `as_of` | 資料產生時的臺北日期，與行情日分開 |
| `trade_date` | 本份行情所屬日期 |
| `session` | `closed`、`scheduled_open`、`unknown`；預定開市不等於確認市場正在交易 |
| `reason_code` | `announced_closed`、`scheduled_closed`、`weekend`、`scheduled_open`、`calendar_unknown` |
| `reason`、`source_url` | 日曆或核對公告的說明及連結 |
| `expected_trade_date` | 當日預定開市且 14 時後採當日，其餘採之前最近交易日；日曆未知為 null |
| `data_status` | `current`、`delayed`、`unconfirmed`、`invalid`；只表日期與整體行情檢查結果 |
| `daily_returns_status` | `available` 或 `unavailable`；後者不把零值列為全市場持平 |
| `daily_returns_reason` | 不可排行原因；正常為 null |

整體異常：行情日是已知休市日，或至少 10 檔樣本都沒有正且有限的成交量。資料異常時，各區間排行暫不呈現，避免錯誤期末行情影響週月。有效行情中的個別持平仍保留為零。

休市文案明寫「2026-10-26 休市」，不對舊快照寫「今日休市」。舊版 JSON 沒有新欄位時明示狀態尚未提供。未取得的日期與數值不以行情日、零或相鄰日補上。
